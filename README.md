# Commons

Открытая мастерская проектов. Любой может опубликовать замысел или присоединиться к чужому проекту, взять задачу по своему ремеслу — код, дизайн, 3D, иллюстрация, тексты, музыка, тестирование, документация — и увидеть, как его работа становится частью общего результата.

Сама платформа делается так же: на сайте один стартовый проект — **Commons**. Идеи пишут в его обсуждение «Идеи для Commons», задачи берут с его доски.

## Что умеет

Проект устроен как репозиторий на GitHub, только вместо кода — общая работа людей разных ремёсел.

- **Обзор** — документы, концепция, стадия, этапы, версии, участники, соцсети проекта, страна, откуда он, и страны участников.
- **Задачи** (как Issues) и **вклады** (как pull requests) с отзывами и правилом принятия: «только автор», «любой сопровождающий» или «два одобрения».
- **Объявления** — планы, новости и «ищем людей» от авторов.
- **Обсуждения** с фиксацией решений, **чат проекта**, **версии**, **история**, **ответвления**.
- **Вклад и доходы** — кто сколько сил вложил (очки по понятным правилам), прогноз дохода после публикации, варианты дележа (по вкладу, поровну, смешанно) и статус «делится ли автор доходом». Это оценка, а не договор.
- **Профили** — свои проекты, проекты, где человек работает, работы вне проектов (с встроенным видео, макетом или моделью), соцсети, страна, календарь активности.
- **Личные сообщения** и **приглашения в проект** — можно сразу предложить конкретную задачу.
- **Пять языков интерфейса** — English, русский, қазақша, 中文, 日本語. Светлая и тёмная тема.
- **Перевод материалов и сообщений** — встроенным переводчиком браузера (свежий Chrome) или через Claude.
- **Встраивания** — ссылка на YouTube, Vimeo, Figma, Sketchfab, SoundCloud, Spotify или картинку отдельной строкой показывается плеером.
- **Вход через Google** — если указан Client ID (см. ниже).

### Помощник

Объясняет проект новичку, подсказывает, с чего начать, пишет техническое задание, разбивает цель на задачи, переводит задачу на язык другого ремесла, проверяет вклад и готовит сводку «Состояние проекта». Принимать вклады он не может — это решают люди. Два режима: встроенный (без сети) и Claude (по ключу API пользователя, ключ хранится только в его браузере). Claude отвечает на языке интерфейса.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5190
npm test         # правила платформы, сервер, помощник, словари переводов
npm run build    # сборка в dist/
```

Без настроек сайт работает как демо: всё хранится в браузере.

### Общая база (Supabase)

Проекты, профили, чаты и сообщения хранятся в Supabase и видны всем. Читать публичное может любой, даже без входа; личные сообщения и приглашения видят только их участники. Писать напрямую в базу нельзя: каждое действие выполняет серверная функция `ops` — она проверяет права теми же правилами, что и интерфейс (`src/data/ops.ts`, `src/data/community.ts`). Интерфейс применяет действие сразу, а изменения других людей приходят мгновенно (Realtime).

Локально (нужен Docker):

```bash
npm run db:start          # своя база на портах 553xx (не мешает Sauda)
npm run seed:db           # стартовый проект Commons
npm run functions:serve   # серверная функция ops (оставить работать)
npm run smoke:db          # проверка вдвоём: идеи, личные сообщения, права
```

В `.env.local` — `VITE_SUPABASE_URL=http://127.0.0.1:55321` и `VITE_SUPABASE_ANON_KEY` (publishable-ключ из `supabase status`). Письма со входом смотреть в Mailpit: http://127.0.0.1:55324.

В облаке (проект Commons уже создан: `jpdfavftipqmjkzlutju`, Франкфурт; ключи и пароль — в `.env.cloud`, в git не попадает; сайт поверх облака локально — `npx vite --mode cloud`):

1. Создать проект на supabase.com и привязать: `npx supabase link --project-ref <ref>`.
2. Накатить схему: `npx supabase db push`.
3. Задать секрет команды платформы и выложить функцию: `npx supabase secrets set COMMONS_ADMINS=почта@пример.com`, затем `npm run deploy:functions`.
4. Положить стартовый проект: `SUPABASE_URL=… SUPABASE_SERVICE_ROLE_KEY=… npm run seed:db`.
5. Хранилище файлов создаётся миграцией `…_files.sql`. Если `db push` не может подключиться к базе, миграцию можно выполнить через API: `npx supabase db query --linked -f <файл>`.
6. Настройки входа облака — в `supabase-cloud/supabase/config.toml` (`npx supabase config push --workdir supabase-cloud --project-ref jpdfavftipqmjkzlutju`). Письмо с кодом вместо ссылки и письма всем, а не только участникам организации Supabase, требуют своего SMTP (Authentication → Emails → SMTP Settings). До этого сайт принимает и ссылку из стандартного письма.
7. Для GitHub Pages: Settings → Secrets and variables → Actions → Variables → `SUPABASE_URL` и `SUPABASE_ANON_KEY` (publishable-ключ).

### Вход через Google

1. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создайте OAuth Client ID типа «Web application».
2. В «Authorized JavaScript origins» добавьте `http://localhost:5190` и адрес сайта (например, `https://backwardzz.github.io`).
3. В Supabase: Authentication → Providers → Google — включить, вписать Client ID и Client Secret, включить «Skip nonce check». Локально — в `supabase/.env` (`SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID`, `…_SECRET`) и `enabled = true` в `supabase/config.toml`.
4. Тот же Client ID — в `VITE_GOOGLE_CLIENT_ID` (`.env.local`) и в переменную репозитория `GOOGLE_CLIENT_ID`.

Без общей базы Google только подтверждает личность, а профиль создаётся на этом устройстве.

## Устройство

- React 18 + Vite + TypeScript, HashRouter — сборка открывается с любого статического хостинга.
- `src/data/types.ts` — модель данных; `src/data/ops.ts` и `src/data/community.ts` — все действия и права как чистые функции; `src/data/registry.ts` — какие действия можно выполнить на сервере; `src/data/runtime.ts` — время и id, одинаковые у браузера и сервера.
- `src/data/store.ts` — хранилище, страницы меняют данные через `act(имя, аргументы)`; `src/data/backend.ts` — связь с Supabase; `src/data/entities.ts` — раскладка данных по строкам таблицы `entities` и правила видимости.
- `src/server/core.ts` — ядро серверной функции (собирается в `supabase/functions/ops/core.js`); `supabase/migrations/` — схема базы.
- `src/data/seed.ts` — стартовый проект; `src/data/fixture.ts` — набор данных для тестов.
- `src/i18n/` — переводы. Ключ — русский текст в `tr('…')`, словари `en/kk/zh/ja.ts`. Тест `i18n.test.ts` проверяет, что у каждой строки есть перевод на все языки.

## Ограничения

- Файлы во вкладах: с общей базой — в корзине `files` хранилища Supabase (до 20 МБ, до 10 файлов, только в папку автора; незнакомые типы сохраняются как `application/octet-stream` и скачиваются), в демо — внутри браузера, до 1 МБ. Файлы больше — ссылкой. Если автор убрал файл из уже отправленного вклада, файл остаётся в хранилище.
- Серверная функция читает всю базу на каждое действие — для начала этого хватит, при росте нужно читать только данные проекта.
- Следующие шаги: уведомления, двусторонние интеграции с GitHub и Figma.
